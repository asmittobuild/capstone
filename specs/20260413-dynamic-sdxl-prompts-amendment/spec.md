# Feature Specification: Dynamic SDXL Prompt Generation Amendment

**Feature Branch**: `20260413-dynamic-sdxl-prompts-amendment`
**Created**: 2026-04-13
**Status**: Draft
**Input**: Amendment: The system must generate both positive and negative prompts for SDXL image generation using the Hugging Face API, based on fusion details, instead of hardcoded templates.

## User Scenarios & Testing

### User Story 1 - Dynamic Prompt Generation for SDXL (Priority: P1)

When a fusion is generated, the system uses the Hugging Face API to create both a positive prompt and a negative prompt for image generation, using the fusion's name and description as input. These prompts are then used in the SDXL image generation request.

**Why this priority**: Ensures image generation is context-aware, flexible, and can adapt to new requirements or styles without code changes.

**Independent Test**: Can be fully tested by generating a fusion and verifying that the prompts sent to the SDXL API are dynamically generated by the Hugging Face API, not hardcoded.

**Acceptance Scenarios**:

1. **Given** a fusion is being generated, **When** the system prepares to generate an image, **Then** it requests both a positive and negative prompt from the Hugging Face API using the fusion's details.
2. **Given** the Hugging Face API is unavailable, **When** a prompt generation is attempted, **Then** the system falls back to a default or error state and does not block fusion generation.
3. **Given** a fusion is generated, **When** the SDXL API is called, **Then** the request includes the dynamically generated prompts.

---

## Requirements

- The system MUST use the Hugging Face API to generate both positive and negative prompts for SDXL image generation, using both the fusion's name and description as input.
- The system MUST NOT use hardcoded prompt templates for SDXL image generation.
- The system MUST gracefully handle Hugging Face API errors or unavailability, falling back to a default or error state without blocking fusion generation.
- The system MUST log or surface errors in prompt generation for debugging and support.

## Success Criteria

- 100% of SDXL image generation requests use prompts generated by the Hugging Face API.
- Fusion generation is never blocked by prompt generation errors; fallback behavior is clear and user-friendly.
- All changes are traceable to this amendment and do not modify the original spec's requirements directly.

## Assumptions

- The Hugging Face API is capable of generating suitable prompts for SDXL image generation given a fusion's name and description.
- The SDXL API accepts and uses the provided prompts as intended.
- The amendment is referenced in all related tasks and plans.
